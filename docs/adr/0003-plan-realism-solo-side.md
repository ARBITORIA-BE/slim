### 기존 PLAN의 비현실성

기존 PLAN.md는 페이즈 0~7을 **12주(=3개월)** 안에 완료하는 일정으로 작성됐다.
이는 MONETIZATION.md의 비용 구성("인건비 €55K = 4명 풀타임 + 2 파트") 과 짝을
이룬다. 즉 **풀타임 4명 팀** 가정이 PLAN의 묵시적 전제다.

운영자 현실(주 10-20시간 + 개발 3개월)에서 풀타임 4명 12주 일정을 그대로 두면:

1. 매 페이즈가 데드라인 미스 → harness:plan 게이트가 만성 적자
2. 페이즈 5(멀티 카테고리)가 페이즈 4(단일 카테고리 검증) 신호 없이 시작 →
   잘못된 카테고리에 시간 매몰 위험
3. 운영 부채(fetcher hack, type assertion, 미작성 runbook)가 페이즈 사이에
   누적되는데 정리 시점이 페이즈 0.5에만 있음 — 페이즈 1~7 사이에는 부재

### 카테고리 우선순위 — 베네룩스 시장 외부 사실

기존 PLAN은 페이즈 1.8을 **에너지 BE (Engie / Luminus / TotalEnergies)** 로
지정. 그러나 외부 검증 결과:

| 출처 | 사실 |
|---|---|
| [VREG](https://www.vreg.be/en/energy-market) | 플랜더스 정부가 직접 V-test 운영 (공식 비교) |
| [CREG](https://www.creg.be/en/themas/price-evolution) | 연방 규제기관이 CREG-Scan 운영 + Energyprice.be 인증 |
| [DareToCompare.be](https://www.daretocompare.be/energy) | "free alternative for the VREG V-test or CREG-Scan", 모든 공급사 포함 |
| [Energyprice.be](https://www.energyprice.be/) | "platform certified by the CREG" |

즉 BE 에너지는 **정부 인증 비교 + 인증 민간 비교 + free alternative까지 3중**.
솔로 신생 사이트가 정면에서 차별화하기에는 (a) 사용자 신뢰 확보 비용이 크고
(b) CREG/VREG 방법론과 어긋나는 즉시 노이즈 분류된다. 통신(모바일/인터넷)은
이런 정부 인증 비교가 부재하고, 어필리에이트 단가 €15~€120(인터넷 LTV 큼)이
기존 MONETIZATION.md §A 표의 €25~€70 가정과 일치한다.

### PLAN 매핑

이 ADR은 PLAN.md 전체 페이즈에 영향. 특히:
- 페이즈 1: 카테고리 변경 (에너지 → 통신)
- 페이즈 1.5/3.5/4.5: 신설 (운영 부채 트랙)
- 페이즈 4: 원 페이즈 4 + 페이즈 7 통합 (베타 + 런치)
- 페이즈 5: 6개월 평가 게이트 (페이즈 4.5)에 의한 조건부 진입
- 페이즈 7: 시드/풀타임 전환 평가 자리홀더

## Decision

### 결정 1 — 카테고리 우선순위: **통신(BE 모바일/인터넷) 먼저**, 에너지는 페이즈 5

페이즈 1.8 fetcher 3개를 **Proximus / Orange BE / Telenet** 로 변경.

**근거:**
- 베네룩스 에너지 비교는 정부 인증(V-test/CREG-Scan) + 민간 인증(Energyprice.be)
  + 무료 대안(DareToCompare)으로 **3중 포화**. 솔로가 정면에서 차별화 어려움.
- 통신은 통합 비교 도구가 분산되어 있어 신생 사이트의 진입 여지가 있음.
- 어필리에이트 단가(MONETIZATION.md §A): 인터넷 €40~€120, 모바일 €15~€40 →
  솔로의 적은 트래픽에서도 단건 수익이 의미 있음 (인터넷 LTV 큼).
- 운영자 기존 자산: salair-plus.com이 BE/LU 임금 계산 도구로 추정됨 → 통신
  요금(소득 대비 비중 큰) 문맥에서 같은 사용자 풀에 마케팅 가능.

**트레이드오프:**
- ✅ 신뢰 확보 비용 낮음 (정부 인증 도구와 직접 경쟁 안 함)
- ✅ 어필리에이트 단가 안정적, 인터넷은 €70 평균
- ⚠️ 통신사 가격 페이지가 자주 A/B 테스트 → fetcher 깨짐 빈도가 에너지보다
  높을 수 있음. 1.5.2의 `harness:price` 일 1회 cron이 이 리스크의 안전망.
- ⚠️ 에너지가 베네룩스에서 *가장 큰 카테고리*인데 후순위 → 페이즈 5에서 진입
  시 V-test 등의 권위 도구와 차별화 포인트(투명성 KPI, 가격 시계열, 다국어)를
  ADR-XXXX(미래)로 별도 결정.

### 결정 2 — 페이즈 5는 **M16 6개월 평가 게이트** 통과 시에만 진입

페이즈 4 베타/런치 후 페이즈 4.5의 평가 조건 4개를 모두 통과해야 페이즈 5
시작:
1. 통신 BE 월 매출 ≥ €1,000 (CPA 어트리뷰션 검증됨)
2. 비교 → 변경 CVR ≥ 3% (보수적 벤치)
3. fetcher 안정성 ≥ 95% (24h 신선도)
4. 운영자 시간 여유 ≥ 주 10h (사이드 유지 가능 신호)

미통과 시: 통신 카테고리 깊이 확장(NL/LU 통신, 부가 기능) 또는 보류.

**근거:** 솔로 사이드에서 검증 안 된 카테고리에 시간을 매몰하면 회복 불가.
4가지 신호는 *수익 / 사용자 행동 / 기술 / 운영자 자신* 4축의 최소 신호.

### 결정 3 — 페이즈마다 **운영 부채 트랙(X.5) 신설**

페이즈 0.5(이미 존재) 패턴을 페이즈 1.5 / 3.5 / 4.5에 복제.
- 1.5: fetcher 공통화 + harness:price 가동 + runbook
- 3.5: Lighthouse/axe 자동화 + SEO + 부하 테스트
- 4.5: 어드민 v0 + Sentry/Inngest 모니터 + 6개월 평가 시작

**근거:** ADR-0002 (Build gate)가 0.5에서 한 일을 페이즈마다 한 번씩 — 솔로는
부채 누적이 곧 페이즈 마비. 페이즈 2.5 / 5.5 / 6.5는 신설 안 함 — 페이즈 2,
5, 6 자체가 다음 X.5에 흡수되거나 길이가 짧아 별도 트랙이 과도.

### 결정 4 — 원 페이즈 4(전환) + 페이즈 7(런치)을 **새 페이즈 4** 로 통합

이유: 솔로에서 어트리뷰션 코드 + 베타 모집 + PR 매체 컨택 + 런치 결정을 두
페이즈로 나눠도 작업 자원이 분리되지 않음 (한 사람이 같은 시기에). 한 페이즈
3개월(M8~M10)로 통합 — 일정 가시성 향상.

### 결정 5 — 일정 단위를 **주차 → M (Month, 솔로 사이드)** 로 변경

작업 추적 메타 표에 "현실 일정 (솔로 사이드)" 컬럼 추가. 풀타임 가정 12주 →
솔로 사이드 **M0 ~ M24** (18-24개월). 18은 모든 scope cut 적용 + 막힘 없는
이상 케이스, 24는 평균 케이스. 24+는 페이즈 7의 시드/풀타임 전환 평가 시점.

### 결정 6 — Scope cut 옵션 5개를 **명시 + 사용자 승인 시 적용**

PLAN.md 끝에 옵션 A~E를 명시. 페이즈 진입 시점에 운영자가 시간/예산 여유로
선택. 사용자 승인 없이 architect 단독 cut 안 함.

## Alternatives considered

### 대안 A — 풀타임 가정 유지 (12주 페이즈 7까지)

- **거부 사유**: FOUNDER.md 사실(주 10-20시간, 개발 3개월)과 직접 충돌. 매
  페이즈가 데드라인 미스 → harness:plan 게이트가 만성 적자. 헌법 P4
  (typecheck 0 에러)를 지키는 데도 시간이 부족해질 위험.

### 대안 B — 5개 카테고리 동시 시작 (원 페이즈 5 그대로)

- **거부 사유**: 솔로에서 fetcher 6개(통신) + 2개(보험) + 2개(금융) + 2개(여행)
  = 12개를 4주에 만드는 것은 불가능. 검증 안 된 카테고리에 시간 매몰 = 회복
  불가. 원 PLAN 페이즈 5는 풀타임 4명 가정의 산물.

### 대안 C — 에너지 카테고리 유지 (단순히 일정만 늘림)

- **거부 사유**: 일정만 늘려도 V-test/CREG-Scan/DareToCompare/Energyprice 4개
  대안과 정면 경쟁하는 신생 솔로 사이트의 신뢰 확보 비용이 크다. "왜 정부
  인증 도구를 두고 Slim?" 답을 베타 100명에게 일관되게 주기 어려움. 통신은
  이 질문 자체가 약함 (포화 안 됨).

### 대안 D — 페이즈 0.5 외에는 운영 부채 트랙 없음

- **거부 사유**: ADR-0002의 학습 — 부채는 페이즈 종료 시점에 표면화된다. 솔로는
  표면화 후 정리 미루면 다음 페이즈가 마비. 페이즈마다 작은 X.5는 운영
  지속성 비용보다 작다.

### 대안 E — 페이즈 5를 *시간 기준* 으로 시작 (예: 무조건 M12)

- **거부 사유**: 신호(매출/CVR/안정성/시간) 없이 카테고리 추가 시 첫 카테고리도
  검증 안 된 채 두 번째 카테고리에 시간 분산. 게이트 기반(4개 조건)이 솔로
  현실에 더 부합.

## Consequences

### ✅ 얻는 것

- PLAN.md가 운영자 현실(솔로 + 사이드 + 3개월 경력)과 정합
- harness:plan 게이트가 만성 적자에서 벗어남 — 데드라인 미스가 의도된 일정
  내에 포함됨
- 카테고리 우선순위가 시장 사실(정부 인증 도구 포화)과 일치
- 운영 부채 누적 시점이 페이즈마다 정리 → 솔로 마비 위험 감소
- 페이즈 5의 6개월 평가 게이트로 잘못된 카테고리 매몰 방지
- Scope cut 옵션 명시 → 운영자가 페이즈 진입 시 의식적 선택

### ⚠️ 잃는 것 / 부채

- 출시 시점이 12주 → M10 베타 + M16 평가 → 약 4-5배 지연. 시장 윈도우 리스크
  (베네룩스 비교 시장 자체가 변할 수 있음).
- 통신 카테고리 우선 → 에너지(가장 큰 카테고리)의 사용자 획득 기회 후순위.
- 페이즈 5 진입 게이트가 4개 조건 ALL → 한 조건만 미달도 보류 → 매우
  보수적. 시드 모금/풀타임 전환 시(페이즈 7) 게이트 자체를 ADR-XXXX로 재검토
  필요.
- 페이즈 7이 "예약 페이지"가 됨 → M24+ 에서 별도 ADR로 풀타임/시드 결정

## 검증 방법

### 검증 1 — 페이즈별 실측 vs 가정 일정 비교

각 페이즈 종료 시 작업 추적 메타 표에 `actual M` 컬럼을 추가해 실제 소요
개월을 기록. `actual / planned` 비율이:
- ≤ 1.2: 계속 진행, 다음 페이즈 가정 유지
- 1.2 ~ 1.5: 다음 페이즈 일정에 +20% 보정
- > 1.5: ADR-0003 본문 재검토 (Amendment 필요할 수 있음)

이 데이터는 페이즈 5 진입 게이트의 4번째 조건(시간 여유) 평가에도 사용됨.

### 검증 2 — 카테고리 우선순위 (결정 1) 검증

페이즈 4.5 시점에 4개 신호 측정:
- 통신 BE 월 매출 ≥ €1,000?
- CVR ≥ 3%?
- fetcher 안정성 ≥ 95%?
- 운영자 시간 여유 ≥ 주 10h?

3개 이상 통과 시 결정 1 채택 정당화. 2개 이하 시 ADR-0003 Amendment로 카테고리
재검토 (에너지로 회귀 또는 다른 카테고리 평가).

### 검증 3 — 운영 부채 트랙 (결정 3) 효과

페이즈 1.5 / 3.5 / 4.5 종료 시 verifier가 확인:
- typecheck/lint/test 0 에러
- 신설 도구(runbook, 부하 테스트, 어드민 v0) 존재
- 그 다음 페이즈가 부채로 인한 차단 없이 시작

3 페이즈 모두 만족 시 X.5 패턴을 페이즈 6.5로도 확장 검토.
