## 맥락 (Context)

### 트리거 — 운영자 "페이즈 4 완료" 선언 요청

페이즈 4 (어트리뷰션 + 완성, M8~M10) 자식 항목 18개 중:

페이즈 5 (5.1~5.4)는 ADR-0034 D2로 "범위 밖" 처리됨 → 페이즈 4가 사실상 프로젝트 마지막 활성 페이즈. 운영자가 페이즈 4를 종료 선언하려면 두 [~] 자식의 처리 규칙이 필요.

## 결정 (Decision)

### D1. 4.5.2 부모 [~] → [x] 격상

**근거**: ADR-0045 §D2 동형 — Claude 트랙 (Sentry init 4 파일 + next.config.ts `withSentryConfig` + `docs/runbook/sentry-alert-rules.md` + `docs/runbook/inngest-alert-rules.md`) 머지 완료. 운영자 cloud dashboard 트랙 = 운영자 결정 가능 시점 별 트랙. 4.12 (외부 변호사 €800)/4.16 (sweep 5건 완료 후 dashboard 별)/4.17 (verifier 룰 GREEN 후 격상)과 동형.

**잔여 표기**: 부모 [x] 본문에 "**운영자 dashboard 트랙 별 진행**" 명시 + 자식 4.5.2.a/4.5.2.b는 [~] 유지 (자식 진행 상태는 정직 보존, 부모는 ADR-0045 §D2 잠금).

### D2. 4.5.3 부모 [~] 유지 + "시간 트랙" 분류 마킹

**근거**: 6개월 운영 메트릭 회고 = 시간 경과 + 인간 판단 의존. 운영자가 "지금 결정"으로 잠글 수 있는 작업이 0. ADR-0045 §D2 동형 패턴 ≠ 적용. P3 정합.

**PLAN 본문 정정**: 4.5.3 본문 "4.5.2 / 4.12 / 4.16 동형 패턴" → "**시간 트랙 (운영 평가 = 베타 진입 + 6개월 시간 경과 의존)**" 으로 분류 변경. 동형 오인용 봉합.

### D3. 페이즈 4 헤더 "Claude 트랙 완료" 마킹

페이즈 4 본문 헤더 (`## 페이즈 4 · 어트리뷰션 + 완성`) 하단에 **2026-06-10 완료 (Claude 트랙)** 잠금 줄 추가:

### 옵션 C: 4.5.3을 페이즈 4 → 페이즈 6 (운영 인프라) 이동

거부 사유: 항목 재분류 = ADR-0034 §결정 1·4·5 cross-ref 영향 + 4.5.1.b 어드민 메트릭 cross-ref (`docs/m16-eval.md`)이 페이즈 4.5 내 정합. 페이즈 6은 "런치 후 일반 운영 인프라" 범위 → 운영 평가 회고를 분리 = 추적 산만. 분류 변경 (D2) 으로 동일 효과 + 이동 비용 0.
